CREDENTIAL ISSUANCE — FULL END-TO-END FLOW
==========================================
  Credential Request Generator Job
          → POST /issue (Credential Service)
          → WebSub CREDENTIAL_ISSUED
          → IDA processes & stores identity
          → WebSub STORED
          → Credential Request Generator updated


============================================================
PART 1 — CREDENTIAL REQUEST GENERATOR JOB calls POST /issue
============================================================

credential-request-generator job triggers:
  POST /issue  →  CredentialStoreController  →  CredentialStoreServiceImpl.createCredentialIssuance()

SERVICES CALLED:
----------------
1.  Partner Management Service       — GET policy by partnerId + credentialType
                                       /v1/partnermanager/partners/{partnerId}/credentialtype/{credentialType}/policies

2.  Partner Management Service       — GET bio extractor formats by partnerId + policyId
                                       /v1/partnermanager/partners/{partnerId}/bioextractors/{policyId}

3.  VID Service                      — GET UIN by VID (only if id is a VID)

4.  ID Repository (Identity Service) — POST fetch identity by id
    4a. VID Service                  — GET UIN by VID (inside ID repo, if idType=VID)
    4b. DB (uin_repo)                — findByUinHash / getUinHashByRid
    4c. DB (uin_history_repo)        — getUinHashByRid (fallback for RID)
    4d. DB (uin_hash_salt_repo)      — retrieveSaltById (for UIN hashing)
    4e. Object Store                 — GET biometric file per biometric record (if type=bio/all)
    4f. Object Store                 — GET demographic document per document record (if type=demo/all)
    4g. Biometric Extraction Service — extractTemplate per modality (if extraction formats provided)

5.  KeyManager                       — POST /jwtSign (digital signature)
                                       KEYMANAGER_JWTSIGN → /v1/keymanager/jwtSign

6.  DataShare Service                — POST multipart upload (only if policy typeOfShare = "Data Share")
                                       POST /create/{policyId}/{subscriberId}
    6a. Partner Management Service   — GET policy by policyId + subscriberId
                                       PARTNER_POLICY → /partnermanager/partners/{partnerId}/policies/{policyId} [cached]
    6b. KeyManager / CryptoManager   — POST /encrypt (only if encryptionType = "Partner Based")
                                       CRYPTOMANAGER_ENCRYPT → /v1/cryptomanager/encrypt
    6c. KeyManager                   — POST /jwtSign (SHA256 digest of file embedded in payload)
                                       KEYMANAGER_JWTSIGN → /v1/keymanager/jwtSign
    6d. Object Store                 — putObject + addObjectMetaData (direct adapter, no HTTP)

7.  KeyManager / CryptoManager       — POST /encrypt (only if NOT Data Share)
                                       CRYPTOMANAGER_ENCRYPT → /v1/cryptomanager/encrypt
                                       Request: { applicationId: "PARTNER", referenceId: partnerId, data: base64(credentialJSON) }

8.  WebSub Hub                       — registerTopic + publishUpdate
                                       registerTopic: {issuer}/CREDENTIAL_ISSUED  [cached]
                                       publishUpdate payload:
                                         { credential (encrypted) OR dataShareUri,
                                           proof: { signature },
                                           credentialType, protectionKey, transactionId }

RESPONSE: CredentialServiceResponseDto
  { status: "ISSUED", credentialId, issuanceDate, signature, dataShareUrl? }


============================================================
PART 2 — IDA (ID-Authentication) SUBSCRIBES & PROCESSES
============================================================

IDA subscribes to WebSub topic: {partnerId}/CREDENTIAL_ISSUED

PHASE 1 — Receive & Store Event
---------------------------------
  IdChangeEventHandlerServiceImpl.handleCredentialIssued(eventModel)
  └─► credentialStoreService.storeEventModel(eventModel)
        → INSERT into credential_event_store
          { id, credentialTransactionId, requestId,
            status: "NEW", eventModel(JSON), createDTimes }

PHASE 2 — Batch Processing
---------------------------
  @Scheduled fixedDelay=${ida.batch.credential.store.job.delay:1000}ms
  CredentialStoreTasklet.execute()
    → credentialEventRepo.findNewOrFailedEvents(pageSize=100)
    → ForkJoinPool (threads: ida.batch.credential.store.thread.count=10)

  Per event — CredentialStoreServiceImpl.doProcessCredentialStoreEvent():
  -----------------------------------------------------------------------
  A) Parse EventModel JSON from credential_event_store
     Extract from event.data:
       - dataShareUri
       - MODULO, SALT
       - demoEncryptedRandomKey  (RSA-encrypted AES key for demographics)
       - bioEncryptedRandomKey   (RSA-encrypted AES key for biometrics)
       - idHash, transactionLimit, expiryTimestamp, tokenId

  B) Save salt:
     → INSERT into ida_uin_hash_salt { idHash, MODULO, SALT }

  C) Re-encrypt random keys under IDA's own KMS:
     → securityManager.reEncryptAndStoreRandomKey(idHash,
         demoEncryptedRandomKey, bioEncryptedRandomKey)
       [key rotation — re-encrypts under IDA's internal KMS]

  D) Download credential from DataShare:
     → GET {dataShareUri}  (DataShare Service)
       Response: credential JSON
         { demographics: { fullName, dob, gender, phone, ... },
           biometrics:   { finger_Left_Thumb: <base64>,
                           iris_Left: <base64>,
                           face: <base64>, ... } }

  E) Build and store identity entity:
     → splitDemoBioData():
         keys starting with finger/iris/face → biometricData (bytes)
         all other keys                      → demographicData (bytes)
     → identityCacheRepo.findById(idHash) → INSERT or UPDATE
         { idHash, demographicData(bytes), biometricData(bytes),
           expiryTimestamp, transactionLimit, tokenId, updatedDTimes }
     → storeIdentityEntity() → identityCacheRepo.save()

  F) Update event status:
     → credential_event_store → status = "STORED"
     → CredentialStoreStatusEventPublisher.publishEvent()
         topic:   ida-topic-credential-status-update
         payload: { requestId, status: "STORED", updatedDTimes: <UTC> }

PHASE 3 — Status propagates back
----------------------------------
  WebSub → credential-request-generator
    → Updates credential_transaction → status = "STORED"
